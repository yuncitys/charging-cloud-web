# 运营商工作台 V2 设计（预警配置 / 文案 / 下钻）

**Date:** 2026-10-27  
**Status:** Approved  
**Parent:** `docs/superpowers/specs/2026-10-26-operator-workbench-design.md`（V1）  
**Approach:** 方案 1 — 查询时读商户配置 + 忽略表；文案澄清；下钻消费 `stationId`  
**Branches:** 继续 `feature/operator-workbench`（cloud）+ `feature/operator-workbench-web`（web）  
**Scope:** A 预警阈值与忽略 · C 实收文案（不做占桩费）· D 下钻预填（不做枪在线过滤）

## Goal

在 V1 工作台已人工验收的基础上：让预警可调、可消噪；消除经营/财务两套「实收」误解；预警跳转能落到对应站点筛选。

## Decisions（已确认）

| # | 决策 |
|---|------|
| D1 | 占桩费本期不做；C 只做文案区分「经营实收」vs「结算实收」 |
| D2 | 忽略：商户共享；天数可选 3 / 7 / 30，默认 7 |
| D3 | 零收入不加「有枪在线」；维持 V1 营业态 + 实收 0 |
| D4 | 阈值在 **查询层** 生效（改配置立即影响列表，不必为阈值重跑全日表） |
| D5 | 预警设置页每个配置字段必须有含义与作用提示（文案见下） |

## Out of Scope（本 V2）

- 占桩费统计、枪在线过滤  
- 小程序工作台对齐、登录落地页  
- 短信/企微推送、独立预警中心  
- 严格营销增量归因、自定义看板

## A. 预警配置与忽略

### 配置存储

表 `t_operator_workbench_alert_config`（建议）：

- 粒度：`merchant_id` 唯一一行；无行则用内置默认  
- 字段与默认：

| 配置项 | 字段（建议） | 默认 | 判定含义 |
|--------|--------------|------|----------|
| 收入骤降比例 | `drop_ratio_threshold` | 0.50 | 判定日实收 / 近 7 日均值 ≤ 该值则骤降 |
| 骤降基线金额 | `drop_baseline_min` | 100 | 近 7 日均值低于该金额不报骤降（防小站噪音） |
| 故障高发工单数 | `fault_high_min_orders` | 3 | 判定日新建故障工单数 ≥ 该值 |
| 启动成功率阈值 | `start_success_rate_min` | 0.90 | 成功率严格低于该值则报启动失败偏高 |
| 启动失败最少订单 | `start_fail_min_samples` | 10 | `(started + no_response) < 该值` 不报 |

权限：与 `alerts` 相同即可（能看「该处理」就能改本商户阈值）；保存需 `@DataScope` 商户范围。

### 设置 UI

- 入口：工作台「该处理」区块右上角 **预警设置** → 抽屉表单  
- **每个字段旁必须展示提示**（`el-form-item` 的 tip / `el-tooltip` / 表单项下方灰色说明，三选一，全页统一）。提示文案如下（实现可微调标点，语义不得删）：

| 字段标签 | 页面提示（含义 + 作用） |
|----------|-------------------------|
| 收入骤降比例 | 含义：判定日经营实收相对近 7 日均值的比例上限。作用：比例越低越「严」（更容易报骤降）。填 0.5 表示实收不到均价一半才告警。 |
| 骤降基线金额（元） | 含义：近 7 日均值的最低门槛。作用：均值低于该金额的站点不报骤降，避免长期低流水小站误报。 |
| 故障高发（新建工单数） | 含义：判定日新建故障工单数的下限。作用：达到或超过该笔数则进入「故障高发」列表，便于优先派修。 |
| 启动成功率下限 | 含义：启动成功订单占比的最低可接受值。作用：成功率低于该值则告警；调低可减少告警，调高更敏感。 |
| 启动失败最少订单数 | 含义：参与成功率计算的最少样本（启动+无响应）。作用：样本不足不告警，避免「仅 1 单失败」刷屏。 |

抽屉底部说明：「修改后立即作用于预警列表，无需重跑统计任务。预警判定日规则与 V1 相同（选「今日」时看昨日已收口日）。」

### 判定逻辑（查询层）

- 沿用 V1：`periodType=TODAY`（或时段末日为今天）时，四类预警的 **判定日 = 昨日**  
- 读取当前筛选商户的配置（多商户时按行所属 `merchant_id` 取配置；无配置用默认）  
- **骤降 / 零收入**：以工作台日表数据为准，用配置重算是否入选（可不依赖日表 `alert_drop_flag`，或 flag 仅作加速、最终以配置为准）  
- **故障 / 启动失败**：沿用 V1 SQL 源，阈值与最少样本来自配置  
- 结果再扣掉未过期的忽略记录，Top 20 + 严重度排序不变  

### 忽略

表 `t_operator_workbench_alert_dismiss`：

- 键：`merchant_id`, `station_id`, `alert_type`, `expire_at`  
- 另存：`dismiss_days`（3/7/30）、`operator_user_id`、`create_time`  
- 同一商户+站+类型再次忽略：更新 `expire_at`（延长或覆盖）  

交互：

- 预警行：**忽略** → 弹窗/下拉选 3 / 7 / 30 天（默认 7）→ 确认后该行从列表消失（商户内全员）  
- **已忽略**：轻量抽屉/二级列表，展示未过期项，支持 **取消忽略**（删行或 `expire_at=now`）  

API（建议，挂在现有 `OperatorWorkbenchController`）：

| 方法 | 路径 | 权限 |
|------|------|------|
| GET | `/operatorWorkbench/alertConfig` | alerts |
| PUT | `/operatorWorkbench/alertConfig` | alerts |
| POST | `/operatorWorkbench/alerts/dismiss` | alerts |
| GET | `/operatorWorkbench/alerts/dismissed` | alerts |
| DELETE | `/operatorWorkbench/alerts/dismiss/{id}` 或 POST cancel | alerts |

`POST /operatorWorkbench/alerts` 行为：自动排除未过期 dismiss。

## C. 费用文案澄清

| 区块 | 主标签 | 副文案 / 提示 |
|------|--------|----------------|
| 今日经营 | **经营实收** | 与经营报表一致（用户实付汇总口径，同源充电日统计 `merchant_actual_income`） |
| 今日经营费用结构 | 电费 / 服务费 / 优惠 | 不展示占桩费 |
| 钱从哪来 | **结算实收**（列表/卡片原「实收」） | 与站点财务日账单一致；应收字段名与日账单页对齐 |

不改后端金额口径，仅 VO 展示名与前端文案。若需国际化/字典，优先硬编码中文与 V1 页面一致风格。

## D. 下钻预填站点

| 预警类型 | 路由 | 行为 |
|----------|------|------|
| ZERO_INCOME / INCOME_DROP | `/business/businessStatistics` | `created`/`activated` 读 `this.$route.query.stationId`，写入站点筛选并触发一次查询 |
| FAULT_HIGH / START_FAIL | `/device/faultMonitor` | 同上 |

约定：

- query 键名统一 `stationId`（字符串或数字均可，页内 `Number` 规范化）  
- 非法 / 无权限站点：忽略预填，不报错打断页  
- 无 query：与现网一致  

零收入规则：不增加设备在线条件。

## Acceptance

1. 修改骤降比例后刷新「该处理」，列表按新阈值变化（无需跑 Job）  
2. 启动失败在样本 &lt; 配置最少单数时不出现  
3. 忽略 7 天后同商户其他账号看不到该条；到期后可再出现；可取消忽略  
4. 预警设置五个字段均可见含义/作用提示  
5. 经营块显示「经营实收」，财务块显示「结算实收」，无占桩费项  
6. 从预警点进经营报表 / 故障监控时，站点筛选已带上对应站  

## Rollout

1. 执行配置表、忽略表 DDL  
2. 部署 cloud + web（当前工作台分支）  
3. 无需强制回填；旧日表仍可用
